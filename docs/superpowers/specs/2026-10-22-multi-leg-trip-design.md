# flight-sniper: режим поездки из нескольких перелётов

Дата: 2026-10-22. Статус: одобрен владельцем в чате.

## Задача

Новая поездка: Бали → Пхукет → Вьетнам → Филиппины → Бали.

- Вылет с Бали с 15.01 по 22.01.2027 (уточнено владельцем после пробного скана:
  без нижней границы лучший маршрут начинался 08.01).
- Вся поездка — не больше 14 дней.
- В каждой стране — не меньше 3 дней.
- Города во Вьетнаме и на Филиппинах не заданы: бот сам выбирает самую
  выгодную пару.

Бот должен следить за ценами на все перелёты и каждый день показывать самые
дешёвые маршруты целиком. Октябрьский мониторинг BSZ/ALA → HKT/DPS
выключается.

## Замер покрытия кэша (22.10.2026)

Опрос `prices_for_dates`: 30 пар × рынки ru/kg × месяцы 2027-01 и 2027-02,
окно 15.01–08.02, итого 120 запросов, все вернули HTTP 200.

| Перелёт | Дат с ценой | Мин. $ |
|---|---|---|
| DPS-HKT | 25 | 82 |
| HKT-SGN / PQC / CXR / DAD / HAN | 20 / 23 / 24 / 17 / 14 | 90–118 |
| SGN-MNL / SGN-CEB | 16 / 18 | 106 / 97 |
| DAD-MNL / CXR-MNL / PQC-MNL | 7 / 15 / 13 | 108–146 |
| MNL-DPS / CEB-DPS / MPH-DPS | 19 / 6 / 2 | 102 / 144 / 147 |

PPS (Пуэрто-Принсеса) пуст почти во всех парах, в PPS-DPS нет ни одной
записи. Пары HAN-MPH, DAD-MPH и CXR-PPS тоже пусты. Лучший маршрут,
собранный из кэша при минимуме 3 дня в стране:
DPS→HKT 18.01 → SGN 23.01 → MNL 28.01 → DPS 31.01, итого **$406** за одного
взрослого.

## Конфиг

Новая необязательная секция `trip` в `config.yaml`:

```yaml
trip:
  stops:                       # по порядку; в каждой остановке — альтернативные аэропорты
    - [DPS]
    - [HKT]
    - [SGN, HAN, DAD, PQC, CXR]
    - [MNL, CEB, MPH]
    - [DPS]
  earliest_start: "2027-01-15" # вылет первого перелёта не раньше (необязательно)
  latest_start: "2027-01-22"   # вылет первого перелёта не позже
  max_total_days: 14           # от вылета первого до вылета последнего перелёта
  min_stay_days: 3             # разница дат между соседними перелётами
  alert_total_usd: 380         # алерт, когда лучший маршрут дешевле
  top_n: 3
```

Остальное:

- `departure_months: ["2027-01", "2027-02"]`, `timezone: "Asia/Makassar"`,
  `cache_ttl_hours: 3`.
- `Config.trip` — dataclass `TripConfig` или `None`. Если секция есть,
  `Config.routes()` возвращает пары между соседними остановками (все
  комбинации аэропортов), иначе работает по-старому: `origins × destinations`.
  `origins` и `destinations` в режиме поездки могут быть пустыми списками.
- Ошибки секции (меньше двух остановок, пустая остановка, `min_stay_days < 1`,
  неверная дата) дают `ValueError` при загрузке конфига.

## Скан

`aviasales.scan_all` не меняется: он уже обходит `cfg.routes()` × рынки ×
месяцы вылета. 24 пары (без PPS) × 2 рынка × 2 месяца = 96 запросов за скан —
меньше, чем в замере (120 без единой ошибки).

Расписание (`scan.yml`): cron остаётся `0 * * * *`, внутри рана 4 прохода.
`monitor.py scan` выполняется только в первом проходе, `commands` — во всех
четырёх. Кэш на даты через три месяца меняется медленно, а команды
по-прежнему обрабатываются раз в ~14 минут.

`cache_ttl_hours: 3`: при скане раз в час запись остаётся свежей, даже если
один запуск пропущен. `min_offer_lifetime_minutes: 10` остаётся: оффер
попадает в расчёт только со второго скана, в котором его увидели, то есть
однократные фантомы по-прежнему отсекаются.

## Сборщик маршрутов: `src/itinerary.py`

Чистые функции без сети и БД:

```python

class Leg:            # лучшая цена перелёта на дату

    landed_usd: float; airline: str; transfers: int
    market: str; search_url: str; last_seen_at: str

@dataclass(frozen=True)
class Itinerary:
    legs: tuple[Leg, ...]
    total_usd: float

    def airports(self) -> tuple[str, ...]: ...   # набор городов, для разнообразия топа

    #   leg[-1].depart_date - leg[0].depart_date <= max_total_days

```

Перебор ограничен: ~25 дат × 5 × 4 × несколько десятков дат — десятки тысяч
веток. В каждой остановке ветки отсекаются по датам до перехода к следующей.

Вход — `store.fresh_prices` по каждой паре из `cfg.routes()`. Поэтому TTL,
отсев фантомов и фильтр пересадок длиннее `max_transfer_hours` (12 ч) уже
применены при скане. Если перелёт подходящей даты в кэше есть только с
пересадкой длиннее 12 ч, маршрута с ним не будет. Это сознательный выбор.

## Сводка: `src/trip_digest.py`

`runner.run_digest` в режиме поездки вызывает `trip_digest.build_text`
вместо `digest.build_digest_text`. Шаг `_refresh_best_prices` выполняется,
как и раньше: точечный запрос по каждому перелёту лучшего маршрута, четыре
запроса.

Сводка уходит каждый день, без «тихих» дней. Маршрут приходит раз в сутки,
и смысл сводки — видеть сумму каждый день.

```
✈️ Бали → Пхукет → Вьетнам → Филиппины → Бали
Вылет до 22.01 · до 14 дней · от 3 дней в стране

1. $406 за взрослого (вчера $412, −1%)
   18.01 Бали → Пхукет — $86 AirAsia, 1 пересадка
   23.01 Пхукет → Хошимин — $101 VietJet, прямой
   28.01 Хошимин → Манила — $117 Scoot, 1 пересадка
   31.01 Манила → Бали — $102 Cebu Pacific, прямой
   13 дней · ссылки: 1 2 3 4
2. $425 …
3. $427 …

Цены из кэша Aviasales, на одного взрослого, без багажа.
```

- Сумма за вчера: `meta.trip_best_prev`, записывается после каждой отправки.
- Если маршрутов нет, сводка пишет об этом и перечисляет перелёты, для
  которых в кэше нет ни одной подходящей даты.
- Названия городов берутся из `src/cities.py` (добавить вьетнамские и
  филиппинские коды), авиакомпании — из `src/airlines.py` (добавить VJ, VZ,
  FD, 5J, Z2, UO, TR, VU, 9G).
- Если сканы не идут, срабатывает существующий `dead_man_switch`.

## Алерты

`runner._process_alerts` в режиме поездки вызывает `_process_trip_alert`
вместо `rules.find_candidates`. Алерты по отдельным перелётам на 24 парах
бессмысленны и шумны.

- Считается лучший маршрут. Алерт уходит, если `total_usd < alert_total_usd`.
- Дедуп — `store.should_alert` с ключом `trip` и `ALERT_DROP_RATIO` 5%:
  повторный алерт приходит только при падении ещё на 5%.
- Текст — блок «1.» из сводки с заголовком «🟢 Маршрут дешевле $380».
- `/pause` соблюдается.

## Команды

Без изменений. `/threshold` в режиме поездки не меняет `alert_total_usd`:
это в рамки не входит, порог правится в конфиге.

## Расписание и запуск

- `digest.yml`: cron `0 1 * * *` — 09:00 по Бали (Asia/Makassar, UTC+8).
- Отправить локальные коммиты на `origin/main`.
- `gh workflow enable` для `scan`, `digest` и `keepalive`.
- Бэкфилл не запускаем: база не пуста, и он всё равно пропустился бы.
  Первые маршруты появятся после двух обычных сканов, когда офферы пройдут
  порог времени жизни.

## Вне рамок

- Команда `/check`: живой поиск `POST /v1/flight_search` по лучшему маршруту
  по запросу владельца. Это отдельная спецификация. Условия Travelpayouts
  допускают только поиск, инициированный человеком
  (см. `ASSUMPTIONS.md`).
- Учёт багажа и цены на двоих.
- Наземные переезды и открытые маршруты (прилёт в один город, вылет из
  другого).
